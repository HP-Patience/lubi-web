# 专注工作台前端迁移方案

## 目标

把独立静态预览中的“专注工作台”视觉结构迁入真实 Lubi Web，同时保留现有 v14 业务模型、数据写入协议、安全边界、快捷键、错误处理、草稿保护和已有验证。

迁移对象是浏览器呈现层。任务、计时、记录、计划、回顾、设置和备份的业务规则继续由现有模块提供。静态预览只作为视觉基线，不直接接入生产入口。

## 设计北极星

让用户一眼知道当前正在做什么，然后顺手完成下一步。当前任务和当前计时是唯一主焦点；计划、记录、待确认和设置提供上下文，不和主焦点竞争。

共同视觉规则：

- 暖白页面、浅暖表面、墨色正文、低对比灰色辅助信息。
- 暖金只表示当前进行中、当前选中和必要的时间焦点。
- 普通区域使用细边框和留白，不给每个模块增加阴影或强调色。
- 侧栏、顶部栏、按钮和列表沿用同一套 4/8 间距与控件语法。
- 中文文案优先，时间数字使用等宽数字；普通图标继续使用现有图标能力。
- 移动端收窄侧栏，内容按“当前任务 → 计时 → 记录 → 其他”顺序单列排列。

## 目标页面与主动作

| 页面 | 主角 | 主动作 | 现有实现来源 |
|---|---|---|---|
| 今天 | 当前任务与当前计时 | 开始、暂停、结束并记入 | `ui/view.ts`、`ui/tasks.ts`、`ui/daySummary.ts`、`ui/taskList.ts`、`ui/productivity.ts` |
| 计划 | 一周任务安排 | 切换日历 / 甘特 / 列表并调整排期 | `ui/tasks.ts`、`ui/gantt.ts`、`ui/dailyGantt.ts`、`ui/planningViews.ts` |
| 回顾 | 一段时间的真实投入 | 看趋势并决定下周行动 | `ui/review.ts`、`core/metrics.ts` |
| 设置与备份 | 数据状态与恢复入口 | 导出、恢复和修改设置 | `apps/web/src/host/settings.ts`、`host/backups.ts`、`ui/settingsTab.ts` |

## 迁移原则

1. 先建立真实 Web UI 的呈现 seam，再逐页替换 renderer 的外层结构。
2. 不在 `apps/web` 复制任务、记录、计时或统计规则；宿主只组合能力。
3. 不把静态预览的字符串数据、按钮行为或 DOM 直接复制到生产页面。
4. 每次只迁移一个页面的外层结构，保留原 renderer 的数据读取和写入调用。
5. 新结构出现的数据状态必须来自已有接口；读取失败继续显示未知，不显示假零值。
6. 每阶段保持可回滚，旧页面和新页面不能长期并存成两套产品，只允许在迁移分支中短期切换。

## 阶段 0：建立基线与迁移开关

范围：只读和基础设施，不改变用户可见行为。

修改：

- 在 `packages/plugin-runtime/src/ui` 建立统一的 Web 呈现入口或页面 shell seam，负责页面框架、导航状态和当前页面标题。
- 将 Web 专属 CSS 变量集中到现有 `apps/web/src/ui-refinement.css` 或拆为 `apps/web/src/focused-workbench.css`，不修改上游样式文件的原始顺序。
- 为页面入口增加一个仅开发环境可用的迁移开关，默认仍走现有页面；测试可以显式选择新 shell。
- 记录当前页面的桌面、窄屏、浅色和深色截图，以及 `test:layout`、`test:ui-review` 基线。

验收：

- `npm run build`、`npm run test:layout`、`npm run test:ui-review` 通过。
- 开关关闭时现有页面行为和截图不变。
- 新 shell 没有业务数据读写代码。

## 阶段 1：迁移应用外壳与“今天”页面

这是第一阶段的核心交付，完成后可以在真实数据上体验新页面。

修改模块：

- `packages/plugin-runtime/src/ui/view.ts`
  - 保留日期、页签、快捷键、刷新、加载和错误状态。
  - 重做顶部栏和页面导航的 DOM 结构，加入今天 / 计划 / 回顾 / 设置与备份的统一导航语义。
  - 保留 `setDate`、`setTab`、`show`、滚动恢复和焦点恢复。
- `packages/plugin-runtime/src/ui/tasks.ts`
  - 保留计划数据、日历、甘特、列表和排期写入。
  - 把“今天”视图的任务清单、完成进度、待整理、我的用时和待确认区域组合成新 shell 所需的布局。
- `packages/plugin-runtime/src/ui/daySummary.ts`
  - 保留当天摘要和任务完成计算，只调整输出层级。
- `packages/plugin-runtime/src/ui/taskList.ts`
  - 保留任务编辑、完成、开始计时、补记和跳过动作，只更换任务行的视觉结构。
- `packages/plugin-runtime/src/ui/productivity.ts` 或现有计时入口
  - 将实时计时的暂停、恢复、结束并记入接到新计时区域。

主页面结构：

```text
应用外壳
├── 左侧导航：今天 / 计划 / 回顾 / 设置与备份
├── 顶部日期栏：前一天 / 日期 / 后一天 / 今天 / 记录用时 / 新建任务
└── 内容区
    └── 今天
        ├── 今日任务与完成进度
        ├── 当前计时
        ├── 我的用时
        ├── 待确认记录
        └── 今天已记录
```

验收：

- 从真实入口创建任务、完成任务、启动计时、暂停计时、结束并记入，刷新后数据仍然正确。
- 计时不会自动完成任务；待确认记录不会被误显示为已核对实际。
- 读取失败显示未知和重试入口，不能显示空任务或 0 分钟。
- 快捷键 `N`、`T`、左右方向键、`1`、`2` 保持可用。
- 桌面、窄屏、浅色、深色和登录恢复后的焦点行为通过检查。

## 阶段 2：迁移计划页

修改模块：

- `ui/tasks.ts`：保留列表、日历和甘特视图切换，重做页面标题、摘要和主内容列。
- `ui/gantt.ts`、`ui/dailyGantt.ts`：只调整任务块、今天线、网格和拖动反馈的视觉变量。
- `ui/planningViews.ts`、`ui/calendarDay.ts`：保留日期选择、任务点击、拖动、缩放和跨日期逻辑。
- `ui/drag.ts`：不改拖动数据协议，只检查新任务块的可见拖动状态。

布局：

- 周计划作为主区域，未安排任务作为低权重辅助区域。
- 当前日期使用很淡的暖金背景；当前任务使用暖金左边线。
- 已完成排期退到灰度，不使用额外色块。
- 日历、甘特和列表共用同一套标题、筛选和导航控件。

验收：

- 日 / 周 / 月切换，列表 / 日历 / 甘特切换保持原有数据。
- 拖动、伸缩、改期、撤销和并发冲突提示均可观察。
- 甘特图和时间轴在窄屏下允许内部滚动，不产生页面横向溢出。

## 阶段 3：迁移回顾页

修改模块：

- `ui/review.ts`：保留周 / 月 / 年范围、趋势、表格、分类、异常记录和待确认语义。
- `styles/04-review.css` 与 Web 自有覆盖层：把摘要整理为一个主数字、一张主趋势图和下周行动列表。
- 保留数据不足、异常日期、并行记录和支出信息的原有解释。

布局：

- 顶部只突出本期记录总时长。
- 主区域放一张趋势图；分类投入使用轻量列表和细进度条。
- 不新增没有数据来源的 KPI、环比或成功结论。
- 回顾文案使用具体中文上下文，避免模板化英文标签。

验收：

- 周 / 月 / 年切换和图表 / 表格切换可用。
- 数据不足、异常记录和待确认记录的提示没有被视觉弱化到不可见。
- 统计结果与现有 `core/metrics.ts` 输出一致。

## 阶段 4：迁移设置与备份

设置和备份最后迁移，因为它们涉及持久化和恢复风险。

修改模块：

- `apps/web/src/host/settings.ts`：保留设置页入口和保存失败恢复。
- `apps/web/src/host/backups.ts`：保留导出、恢复、大小限制、路径校验和下载行为。
- `packages/plugin-runtime/src/ui/settingsTab.ts`：保留插件设置、分类、AI 设置和密钥边界，只改页面分组和控件呈现。
- `apps/web/src/host/files.ts`、`secrets.ts`：不改变文件与密钥协议。

布局：

- 通用设置、数据文件、备份与恢复分成清楚的分组。
- 数据状态与危险动作保持相邻但视觉分离。
- 恢复动作必须继续显示隔离恢复和不会替换当前文件的说明。

验收：

- 设置保存失败后表单仍保留草稿。
- 三类备份入口文案和行为保持区分。
- 恢复只能写入新隔离目录，不替换活动数据。
- 认证过期、重试和下载行为保持现有结果。

## 样式迁移方式

先把静态预览中的变量转成生产变量，避免在多个选择器里重复颜色：

```css
--lubi-focus-canvas: #f7f5f0;
--lubi-focus-surface: #fbfaf7;
--lubi-focus-ink: #20242a;
--lubi-focus-muted: #73777b;
--lubi-focus-line: #d9d8d2;
--lubi-focus-soft-line: #e5e3dc;
--lubi-focus-accent: #c9963e;
--lubi-focus-accent-soft: #f2e9d6;
```

生产样式只负责视觉和响应式规则，DOM renderer 负责语义、状态和事件。使用现有 `icon()` / `iconButton()` 能力，不能把静态预览中的字符图标迁入生产页面。

## 测试与提交顺序

每个阶段拆成小提交：

1. `refactor: add focused workbench shell seam`
2. `feat: migrate focused today view`
3. `feat: migrate focused planning view`
4. `feat: migrate focused review view`
5. `feat: migrate focused settings view`
6. `chore: remove temporary focused preview route`

每阶段运行：

- `npm run build`
- 相关单文件 / smoke 测试
- `npm run test:layout`
- `npm run test:ui-review`
- 真实浏览器桌面与窄屏截图
- 主要操作从真实入口开始，完成后刷新并读回

最终运行：

- `npm run verify`
- `npm run test:layout`
- `npm run test:ui-review`
- 真实浏览器主流程：登录 → 今天 → 新建任务 → 计时 → 结束并记入 → 回顾 → 设置 / 备份

## 回滚策略

- 阶段 0 的迁移开关可以切回旧 shell。
- 阶段 1 未完成前不删除原 renderer。
- 每个页面迁移完成后才切换默认入口，并保留上一阶段提交可单独回退。
- 不修改数据库 schema、v14 序列化格式、写入版本协议和认证协议。
- 静态预览在真实页面完成验收后删除或移入设计证据目录，不作为第二套生产产品长期保留。

## 明确不做

- 不把静态 HTML 直接挂到真实 API 上。
- 不在 `apps/web` 复制任务和计时业务逻辑。
- 不重新设计数据库、备份格式或认证流程。
- 不同时维护旧 UI 和新 UI 两套长期产品。
- 不把截图像素差异当作功能验收。
