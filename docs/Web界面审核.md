# 第二阶段：Web 界面降噪 · 独立审核版

> 本分支以 `a6c02ea644457cb400153bf208a363fbde4e36c6` 为基线。
> 用户于 2026-10-18 明确允许 Web 布局、折叠、表单顺序和入口位置不同于旧插件。
> **仅供审核：不合并 main，不替换现有正式服务，不连接或部署到用户服务器。**

## 四项变化

1. **摘要更短，异常不藏。** 四个大状态卡改为紧凑摘要；确认为空的后台和用时面板默认收起，空审核卡不再重复占位。有待审核结果时仍跨日期置顶，非重复任务也显示发生日。选中日的用时向存储做新鲜读取；失败显示“暂不可读”，不按 0 统计，日历不绘制假的空时间轴，任务操作仍保留。较慢读取保留上一版结果并明确标注正在更新。
2. **新任务先填三个输入。** 默认只展开任务、计划日期、预计用时。分类、时间、重复、项目、备注等按需展开；可选实际用时独立折叠。折叠保留控件和草稿，不再等同于清空。无效隐藏字段会被展开并聚焦。原有轻量编辑表单、未知元数据合并、并发校验仍保留。
3. **按用途放入口。** 顶栏提供明确的“记用时”；普通新建任务不再因为标题中的 `30min` 自动写实际记录，时间短句解析保留在明确的记用时入口。计时和待整理在计划旁；投入与成果、周复盘在回顾旁。JSON 与 AI 在“更多”，全部 13 个原命令 ID 保留。原来混在一起的五个工具改为各自的弹窗，操作实现不变。
4. **备份说明放在一起。** “更多 → 备份与恢复”以及设置的数据页明确区分三种格式。业务 JSON 只含任务、项目和记录；Web 文件备份保留完整 Web 文件，但**不含设置、计时会话或密钥**；SQLite 整库与本地 key 的备份在本机/服务器命令中处理，`.env.local`、访问密码及外部 `LUBI_SECRET_KEY` 另行保管。两种 JSON 恢复仍走各自解析器并新建隔离目录；网页没有覆盖在线数据库的入口。

## 源码边界：不伪造“原版未改”

- `packages/plugin-runtime/UPSTREAM.json` **原始文件和所有旧哈希均未改写**。
- `packages/plugin-runtime/WEB_UI.json` 是单独的 Web 归属清单：列出 7 个获准改动的 UI 文件、每个原始/当前哈希、原因，以及新增的表单布局模块。
- 核心与服务、v14 数据格式、原始样式文件、后端 API、安全校验和旧版兼容层保持基线代码。没有维护“原样/紧凑”两套产品模式，没有全局 DOM 隐藏补丁。
- 旧测试中的 UI 入口与呈现断言明确改为 Web 契约，变化由 `test/ui-acceptance-manifest.json` 记录；业务数据、并发、撤销、记录、完成、备份恢复等断言保留。
- `test:browser` 的九视图门槛改为当前 Web 布局和真实操作，不再沿用旧 2.5% 像素差门槛。新的 `test:layout` 覆盖多宽度与暗色，以及展开表单/备份/回顾。
- `test:native`、原版参考页生成及原版 layout 运行器设有守卫：在这个改版分支会明确拒绝，不会把改版源码重新截图冒称“原插件”。原始 native/13 项 layout 结果只作为 Phase A 历史记录。
- 用户的 `E:\项目管理\obsidian_task_kanban` 原始 133 文件仍是只读参考；所有改动位于独立审核 worktree。

## 当前验收入口

```bash
npm ci
npm run verify
npm run test:ui-review
npm run test:layout
```

`verify` 包含源码归属检查、结构、构建、旧版 domain/API、Vault/CAS、认证与安全、SQLite 备份恢复、启动器、core/smoke、host 契约、22 组浏览器工作流及第二阶段专项验证。

所有测试使用合成任务、独立临时 SQLite 和模拟 AI，不加载真实 Vault，不调用付费 AI。前后截图固定同一演示数据、时间、视窗；专项错误状态截图单独标注，不能当作同数据前后对照。

## 审核建议

- 先看普通新任务是否足够直接，再展开更多安排/实际用时检查值是否仍在。
- 在计划中找到计时、待整理；在回顾中找到投入与成果和周复盘；“更多”中检查 JSON、AI、备份恢复。
- 留意跨日期审核、明确完成选项和读取失败提示是否容易找到。
- 三种备份说明能否让你直接判断需要导出什么、恢复什么。
